# Working Agreement

This Working Agreement defines how our team will communicate, collaborate, develop code, and handle responsibilities throughout the project. All team members are expected to follow these guidelines and discuss any necessary changes with the group.

## 1. Communication and Availability

Our preferred form of communication will be via **WhatsApp**.

Team members should check group messages regularly and, whenever possible, respond within **24 hours on weekdays**.

Each team member should communicate their general availability to the group. If a member expects to be unavailable for an extended period, they should notify the team in advance.

For urgent matters related to deadlines or project problems, team members should clearly indicate that the message is urgent.

## 2. Team Meetings

The team will meet once per week at the following time:

**Day:** Thursday  
**Time:** 9:45 AM  
**Location/Platform:** Zoom

Additional meetings may be scheduled when necessary, particularly before major project deadlines.

During meetings, the team should:

- Review progress since the previous meeting.
- Discuss open GitHub issues.
- Identify problems or blockers.
- Assign or clarify upcoming tasks.
- Review important Pull Requests when necessary.

## 3. Scripting Practices

To keep the project consistent and easy to maintain, the team will follow these scripting practices:

- Use meaningful names for variables, functions, classes, and files.
- Keep functions reasonably small and focused on a specific task.
- Avoid unnecessary duplication of code.
- Add comments when the purpose of the code is not immediately clear.
- Follow the naming and formatting conventions of the programming language being used.
- Remove debugging code, unused variables, and unnecessary commented-out code before merging.
- Use consistent indentation and formatting throughout the project.
- Use a linter or formatter when one has been adopted by the team.

## 4. Version Control Practices

The team will use **Git and GitHub** for version control.

The following practices should be followed:

- Work should normally be completed on a separate branch rather than directly on the `main` branch.
- Every significant contribution should have a corresponding **GitHub Issue**.
- Branch names should clearly describe the task being completed, for example: `feature-user-login` or `docs-working-agreement`.
- Commits should be reasonably small and focused on a particular change.
- Commit messages should clearly describe what was changed.
- Completed work should be submitted through a **Pull Request (PR)**.
- Pull Requests should reference the corresponding GitHub Issue when applicable.
- Team members should review their changes before merging them into `main`.
- The corresponding issue should be closed once the work has been completed and merged.
- Team members should pull the latest changes from the repository regularly to reduce merge conflicts.

## 5. Testing Practices

Team members are responsible for testing their work before submitting a Pull Request.

Whenever appropriate:

- New functionality should include automated tests.
- Existing tests should continue to pass after changes are made.
- Bugs should include a test when practical to help prevent the same problem from occurring again.
- Tests should cover normal cases as well as important edge cases.
- Team members should run the project's test suite before merging a Pull Request.
- Code that causes existing tests to fail should not normally be merged into `main`.

The team may also configure **GitHub Actions** or another Continuous Integration tool to automatically run tests when Pull Requests are created.

## 6. Missing a Meeting

If a team member knows that they will miss a scheduled meeting, they should notify the group as early as possible.

The absent member should:

- Review any meeting notes or messages after the meeting.
- Check GitHub for new or updated issues.
- Contact another team member if any decisions made during the meeting are unclear.
- Complete any tasks assigned to them unless new arrangements have been agreed upon.

If a team member repeatedly misses meetings without notifying the group, the team should first discuss the issue with that member and attempt to resolve the situation.

## 7. Task Responsibilities

Team members should use GitHub Issues to identify and track project tasks.

When a member accepts responsibility for an issue, they should make a reasonable effort to complete it by the agreed deadline. If they encounter a problem or realize that the task may be delayed, they should inform the group rather than waiting until the deadline.

Team members are encouraged to ask for help when they encounter difficulties.

## 8. Respectful Collaboration

All members should contribute to a respectful and productive working environment.

Team members agree to:

- Listen to each other's ideas.
- Provide constructive feedback.
- Discuss disagreements respectfully.
- Ask questions when requirements or decisions are unclear.
- Give other members reasonable opportunities to contribute.
- Focus discussions on improving the project rather than criticizing individuals.

## 9. Updating This Agreement

This Working Agreement may be modified if the team decides that a different process would improve collaboration.

Any significant changes should be discussed with the group and agreed upon by the team.
